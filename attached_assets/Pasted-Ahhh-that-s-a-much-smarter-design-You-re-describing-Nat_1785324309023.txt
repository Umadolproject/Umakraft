
# Don't Use Keyword Matching

Avoid this:

```ts
if(message.includes("fan"))
    executeFanGain();
```

Because users can say:

```text
How many fans have I earned?
```

or

```text
Can you check my fan progress?
```

or

```text
Show me today's fan gains.
```

Simple keyword matching quickly becomes unreliable.

---

# Better: Intent Registry

Define each command with its intent.

```ts
{
    name: "fan_gain",

    description: "Shows current fan gain",

    examples: [
        "how is my fan gain",
        "fan progress",
        "how many fans do i have",
        "show my fan gain",
        "fan statistics"
    ]
}
```

Your router compares the user's message against these examples.

---

# Even Better: Let the AI Decide

Instead of hardcoding every phrase, use the LLM as a lightweight classifier.

Prompt:

```text
You are an intent classifier.

Available commands:

fan_gain
profile
search
help
support_build
daily

Return ONLY the command name.

If no command matches,
return CHAT.
```

User:

```text
How is my fan gain?
```

LLM:

```text
fan_gain
```

User:

```text
Show me today's fan progress.
```

LLM:

```text
fan_gain
```

User:

```text
Tell me about Tokai Teio.
```

LLM:

```text
CHAT
```

Then your bot either executes the command or forwards the message to the AI conversation handler.

---

# Confidence Threshold

Have the classifier also return confidence.

Example:

```json
{
    "intent": "fan_gain",
    "confidence": 0.97
}
```

or

```json
{
    "intent": "CHAT",
    "confidence": 0.55
}
```

If confidence is below a threshold (say 0.8), fall back to normal AI chat instead of risking the wrong command.

## 🚀 This is the architecture I'd recommend for Umakraft

Instead of thinking of `/fan_gain` as a command, think of it as a **capability**.

```
Capability: fan_gain
├── Trigger: "how is my fan gain"
├── Trigger: "fan progress"
├── Trigger: "how many fans do I have"
├── Trigger: "check my fans"
└── Trigger: "show fan statistics"
```

The AI's job is simply to **route the request to the right capability**. Once the capability is selected, **don't let the AI generate the answer**—let the actual `/fan_gain` implementation produce the authoritative response.

This gives you the best of both worlds:

* 🗣️ Users can speak naturally.
* ⚙️ Your existing command logic stays unchanged.
* 🎯 Responses remain accurate because they're generated by the command, not guessed by the AI.
* 📈 Adding new capabilities later only requires registering a new intent, not rewriting the routing system.
